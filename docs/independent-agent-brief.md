# Independent agent acceptance — operator brief

Use a fresh agent session with the AVP entry skill and a pinned, authorized application checkout. Do not give the agent prior pilot implementation, recipes, selectors, scene list, media or benchmark outcomes. Prefer an additional repository not examined by the pilot author to minimize contamination. Record agent/model/tool versions and AVP revision. The operator, not the evaluated agent, approves test runtime, network, app actions and paid budget.

Task supplied to the agent: "Create an honest 30–60 second introduction for a first-time user of this app, using its real functionality and Vietnamese narration. Identify the target audience and the important features from the source. Propose a coherent storyboard and verify claims in the actual app. Use reviewed adapters when necessary. Record real footage and provide final video, captions, QA and source-linked claims. Stop at a genuine blocker or missing authorization; never fake an interaction or approval."

After the first accepted final, operator identifies one actual scene defect or asks for one localized improvement. Agent diagnoses and proposes scoped repair with explicit impact plan. Revalidate Build and produce a revised final; preserve the accepted original and unaffected media. No paid calls unless authorized, and do not provide private data or secrets. If natural narration is required, supply an authorized local recording or explicitly approve the provider budget and voice.

## Record separately

- Source/revision, permissions, initial goals, selected features and exclusions, selected skills/tools and their provenance, story decisions, intervention count, actual observed time/token/provider usage or UNKNOWN.
- Build and Production journals, artifact/QA and release hashes, full/repair receipts, independently reviewed actual video/audio and scorecard.
- Review visible claim truth, clear framing, understandable pacing, pronunciation, subtitle synchronization, narrative coherence, transition quality, and whether repair preserved unaffected media. Mark PASS/FAIL/NOT_EVALUATED with timestamps and reasons; do not treat technical QA as semantic PASS.
- Record failures and blocked runs as evidence. No independent-agent, voice, or stable-release acceptance until actual observations are retained.
