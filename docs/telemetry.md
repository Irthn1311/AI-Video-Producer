# Execution telemetry (F-05e)

Run `avp telemetry --project DIR` to obtain a JSON report from local journals and current artifacts. Build and Production journal totals count attempted dispatches, executed, failed, reconciled, open/interrupted attempts, retry starts and elapsed milliseconds, grouped by task and scene and by known Production capability. A retry is a repeated task key in the same revision. Reused dispatches and selected-audio copies are explicit outcomes recorded by the executor, not guessed from missing calls. Durations are sums of observed dispatch intervals, not total wall clock or external Agent effort. Journals predating this change remain readable but lack newer outcome fields.

The first Production dispatch for a frozen lock revision records its artifact baseline. The report identifies artifacts that were current at baseline and are still current with identical content hash, input hash and recorded build time. This is a conservative reuse indicator, not evidence of monetary savings or proof of semantic quality. Disabled voice is distinct from cached voice. Current QA status is checked using the existing QA validator. The current lock identifier does not itself establish current Build readiness. Old journals have no baseline and report null instead of inventing reuse.

Provider history distinguishes existing paid reservations from local dispatch-start events and finished audio-format-valid or failed outcomes. A local start does not establish network delivery; a reservation does not establish a charge. Crashes can leave open events or reservations without observed starts. Costs are estimated reservations, not actual bills. Paid consent and existing budget enforcement are unchanged. Phase separates audition from Production; no secret, narration, response body or raw exception is stored in these new events. No external agent tokens/subscription quotas are available.

Workflow capability matching reuses its validated bounded analysis cache and binds the skills cache key to the domain registry. Canonical Build checks still independently inspect source and tooling; this does not eliminate all scans. No automated capability selection from past success rates, quality downgrade or automatic cost optimization is performed. The report covers journaled workflow/production dispatches, not all legacy CLI commands or manual Agent activity. At most 1000 revision journals per phase, with a 16 MiB per-journal bound; incomplete/invalid coverage is explicit.
